# DXFなしで作る搬送エリア論理マップ v0.1

関連：[全体マップ仕様書](specs/08-map.md)・[AGF通行・車線仕様書](specs/09-traffic.md)・[DXF変換仕様](map-dxf-pipeline.md)

## 1. 今回の成果物と区分

| ファイル | 目的 | データ区分 |
| --- | --- | --- |
| [reference-logical-map.json](../data/reference-logical-map.json) | エリア、通行区間、方向、車線、論理接続、設備入口、01～05の搬送元／先、発行制約 | 利用者確認済みの**抽象的な関係**。物理寸法や個別停止点ではない |
| [logical-map.svg](../assets/logical-map.svg) | 論理的なつながりを示す簡略2D概念図 | **模式図**。実座標、縮尺、距離、設備の実配置を表さない |
| [logical-map.mjs](../src/map/logical-map.mjs) | JSON検証と確認済み論理リンクの探索 | **概念経路だけ**。実走行経路・ETAは算出しない |
| [check-logical-map.mjs](../scripts/check-logical-map.mjs) | 通行ルールと未確定区間の検証 | 公開用チェック |

元図・実CAD形状、ファイル名、実座標、画像そのものは公開GitHubへ保存していない。DXFを用意しなくても、**確定した通路間の論理接続をシミュレーターへ渡す**段階まで進められる。

## 2. このJSONの構造

- areas：パレタイズ（PZ）、製品倉庫（WH）、エリア間（INTER）。
- corridors：区間ID、エリア、進行方向、車線数、同時すれ違いの回答、通行可否。geometryStatus はすべて not-measured。
- corridorGroups：PZ通路1・2は各1車線。組合せで双方向2車線扱い。
- links：通路同士の概念接続。confirmed と unresolved を明示し、別の reviewState が一致しなければ確定扱いできない。
- interfaces：PGW8、PM5、包装機1（投入／回収2インターフェース）、OT3、整列機5、充電器2、HP2、倉庫の個別ロケーション。
- accessRules：倉庫西側SH禁止、パレタイズ西入・東出、倉庫東入出、02の同一行置きタスク保留と発行時ロケーション予約、隣接行の減速など。
- taskRoutes：01～05と充電移動の搬送元・先、未確定箇所。
- unresolved：個別停止位置、実通路へのゲート取付け、エリア間詳細、各ロケーションのID・行割当、区間距離・旋回・交通制御詳細。

coordinateSystem: none、hasActualSiteCoordinates: false、hasMeasuredDistances: false により、**JSON内の概念区間IDと実CADのノード座標を混同しない。**

## 3. 通行確認を反映した部分

### パレタイズエリア

走行通路1（PZ-A1）と2（PZ-A2）は全区間通行可能。両端に相互接続があり、PGW／PM／包装機／OT1～3は通路1側へ接続する。各通路は双方向1車線、通路2本を組み合わせて双方向2車線と扱う。各1車線区間内部での「同時すれ違い可能」の具体的な通過形態・排他制御は未確定。

### 製品倉庫

東側・西側縦通路と上下の防火SH接続は双方向2車線・同時すれ違い可能。東西の保管区画アクセスは双方向1車線・交互通行。横1行の置場通路は双方向1車線で、行内同時すれ違い可否は未確定。倉庫西側SHはAGF経路候補から除外する。

同じ行に既存の置きタスクがある間は新しい02を発行しない。02の発行時に搬送先ロケーションの空き・予約状況を確認し、利用可能な位置を予約する。個別位置の座標と行の対応は未確定で、架空の倉庫ロケーションを実施設位置として列挙しない。

## 4. 経路探索に使える範囲

findConceptualPath は**両端が通行可能で、リンクが確認済み**の場合に限り、通路IDの順序を返す。例として、パレタイズ通路2→通路1→設備側、倉庫東縦通路→上段／下段接続→西縦通路の**概念経路**は検証できる。

一方、包装機出口から個別倉庫位置へ至る**完全な物理経路はまだ返さない**。パレタイズ出入口と通路の正確な取付け、エリア間接続、シャッター停止点、倉庫個別行・個別ロケーションへの接続が未確定だからである。未確定リンクを仮に通して所要時間や安全性を算出しない。

このグラフのノードは実座標ではなく通路区間IDである。将来、個別停止点・旋回点・通路のノード／エッジを確定したら、別の物理グラフへ細分化する。AGFが衝突せず通過できることや、実装済みの走行エンジンの存在を意味しない。

## 5. 検証方法

    npm run check:map
    npm run check

テストは、通路1・2の合計車線数と各通路の車線数、倉庫の東西概念接続、禁止した西側SH、未確認のエリア間通行を勝手に許可しないこと、02の同一行保留・発行時予約などを確認する。

## 6. 後続に必要な情報

実行可能な01～05の完全な経路と3時間シミュレーションの移動時間を算出するには、個別荷役停止点・倉庫ロケーションと各行の対応、エリア間通路の接続・各SHの通過停止点、区間距離／速度／旋回条件を追加確認する。DXFによる実寸形状の取込みは[別パイプライン](map-dxf-pipeline.md)として継続可能だが、論理マップを作り始めるための前提条件ではない。
