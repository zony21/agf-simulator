# 区間レビュー・走行候補グラフ契約（M2 / 未完成）

本書は**公開可能なコードの使い方のみ**を説明する。元DXF、実座標、現場の図面画像・レイヤー名、レビュー結果JSONは公開リポジトリに置かない。関連: [実装計画](implementation-plan.md) / [経路図の指定](route-annotation-guide.md) / [進捗Issue #2](https://github.com/zony21/agf-simulator/issues/2)。

## 目的と区別

- `private-route-annotations-v1` は元の**表示下書き**。`draft-only` / `routable=false` / `physicalEtaAllowed=false` を維持する。編集した線を勝手に昇格させない。
- `private-segment-review-v1` は同一SVGのSHA-256、viewBox、ノードID・タイプ・正規化座標、経路の区分・順序に紐づく**別の確認台帳**。線を動かす／経由点を増減する／搬送区分を変更すると以前のレビューは失効する。
- `reviewed-topology-v1` は利用者が区間ごとに通行可能と申告したもののうち、搬送／充電の区分がある区間だけを採録する**位相グラフ**。未割当の参考ガイド、通行不可、未確認区間は含めない。
- 上記グラフも `physicalEtaAllowed=false` / `trafficReady=false` / `operationalRoutingReady=false`。距離の単位照合、車体幅・旋回余裕、実シャッター信号、区間の排他制御を証明しない。現場の安全認証ではない。

## 画面操作

1. AGF図形を除外済みの非公開SVGを端末内で読み込み、同じ画像ハッシュの下書きJSONを読み込む。
2. **最初に参考線と停止／旋回／荷役点の位置を直す**。下書きを変更した後は区間レビューをやり直す。
3. 「区間ごとの通行条件レビュー」で対象を選び、通行可否を申告。通行可の場合のみ、方向・車線数・シャッター有無を**個別に指定**する。同時通過の判断が未確定なら「未確認」のままにする。
4. シャッター制御区間は、設備IDと別登録した`shutter_wait`型の待機点を指定する。点の座標・信号の仕様を推測で追加しない。
5. 非公開の確認台帳JSONを保存する。同じCAD画像・同じ点・同じ経路の場合だけ読込を許可する。
6. 「通行候補グラフJSON保存」で通行可の申告済み・搬送区分設定済みの線だけを出力。**シミュレーションへの物理走行連動はまだ未実装**。

## ソフトウェア契約

`src/map/reviewed-topology.mjs` は次の独立した純粋関数を提供する。

| 関数 | 責務 |
| --- | --- |
| `createSegmentChecklist(annotation)` | 全区間を未確認で初期化。自動承認はしない。 |
| `setSegmentReview(annotation, checklist, value)` | 1区間の明示入力を型・既存点で検証。 |
| `validateSegmentChecklist(annotation, checklist)` | 同一画像／下書き／点順序を照合し、重複・欠落・矛盾を拒否。 |
| `buildReviewedTopology(annotation, checklist)` | 未確認・通行不可・参考ガイドを除外し、距離なし位相グラフを返す。 |
| `findReviewedTopologyPath(graph, fromId, toId)` | 方向に従う位相上の探索結果を返す。所要時間と交通許可は常に未提供。 |

`access`, `direction`, `laneCount`, `simultaneousPassing`, `gate` を独立属性とする。**双方向＝2車線／同時すれ違い可**とは解釈しない。通行不可・未確認なら進行方向等の通行属性を与えず、完全確認されていない通行可申告も受け付けない。シャッター制御に必要な待機点は単なるウェイポイントを代用しない。

## 回帰テスト（合成データのみ）

`npm run check` で、未確認・通行不可・参考ガイド除外、方向制御、レビュー後の点移動／区間分割／区分変更による失効、シャッター待機点の必須化、重複・欠落、距離／ETAなしを確認する。実図面由来のテスト入力は公開リポジトリに置かない。

## 次工程

- M1：実図面の初期参考線と設備別停止点の非公開レビュー。
- M2：実際の共有接続、通行可否・方向・車線・シャッター運用を確認し、実走行用の根拠を持つトポロジーにする。
- M3：縮尺確認済みの距離／速度と区間移動イベントを接続。
- M4：排他・すれ違い・実シャッター通行条件を実装し、運転・安全判断とは分離する。
