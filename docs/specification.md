# AGF搬送シミュレーター 開発仕様書（公開用 v0.2）

> 本書は開発用の公開仕様です。設備の実配置、顧客・現場識別情報、提供資料の原本・名称、実測運転値は含めません。これらは非公開の承認済みシナリオで別管理します。
>
> 本書の「実装予定」は実装済みを意味しません。既存ハーネスの提供範囲は [harness-contract.md](harness-contract.md) を参照してください。

## 1. 目的と対象

- 生産設備からの搬出、搬送車両の割当、荷役、包装、入庫、空パレット補充、待機・充電をイベント駆動で再現する。
- 2D設備図の上に車両位置と工程状態を表示し、シミュレーション時刻で再生・シークする。
- 同一の外生入力、同一の初期状態を使用し、選定方式の違いを比較する。
- イベントログから滞留、スループット、空走、充電待ち、設備占有を検証可能にする。
- **実機の制御・安全装置の代替は対象外**。本システムはオフライン分析専用。

## 2. 根拠区分と公開境界

各設定・表示値に次の区分を付与する。

| 区分 | 意味 |
| --- | --- |
| 承認済み要件 | プロジェクトで確認され、公開可能な範囲に一般化した要件 |
| シナリオ値 | 設備能力、台数、配置、閾値、時間など外部入力する値 |
| 仮定 | 実測未入手の暫定入力。画面・出力で明示する |
| 未確定 | 入力不能または値を使う計算を抑止する |

公開リポジトリには、顧客名、現場名、提供資料のファイル名・原本、実図、実座標、設備固有の能力・運転実績、これらを復元できるデータを置かない。開発・テストには合成データを使用する。

## 3. シミュレーションエンジン

- UIから独立した決定論的な離散イベント方式とする。
- 時刻は非負の整数ミリ秒 `timeMs`、同時刻の順序は `sequence` で定める。
- イベント処理は「前提条件確認 → 状態更新 → 後続イベント発行 → 履歴保存」の順で行う。
- 同じシナリオ・入力イベント・乱数シード・エンジンバージョンから同じ履歴を生成する。
- パレットID、発生ラインID、タスクID、車両ID、設備ID、ロケーションIDを工程間で保持する。
- UIのアニメーション時計が工程の完了時刻を変更してはならない。

### 3.1 イベントの分離

生産完了、搬出可能、搬出実績、タスク要求、割当、到着、荷受け許可、荷受け、移動、荷下ろし、包装開始／完了、ラベル完了、出口準備完了、倉庫入庫、補充要求／投入、充電開始／終了は別イベントとする。許可・準備完了を時間経過だけで擬似的に成立させない。

### 3.2 容量と資源

- 生産ラインの搬出バッファ、包装機の投入・処理中・回収側、パレットマガジン、倉庫ロケーションはそれぞれ別資源。
- 容量はシナリオで設定し、満杯なら新規投入をブロック・保留して、その理由を記録する。
- 車両は同時に1件のみ担当。充電中／充電待ち／異常中の車両を通常搬送に割り当てない。
- 充電設備は設定された同時使用枠を超過させない。
- 同じパレットを複数工程・複数車両に同時占有させない。

## 4. 搬送タスク（シミュレーター内の便宜ID）

| ID | 工程 | 開始条件 | 完了条件 |
| --- | --- | --- | --- |
| 01 | 生産ライン → 包装機投入側 | 搬出実績と荷受け可能条件 | 荷受け・搬送・包装機への荷下ろし完了 |
| 02 | 包装機出口 → 倉庫指定位置 | 包装、必要なラベル工程、出口搬出可能条件の成立 | 指定ロケーションへの荷下ろし・実績登録 |
| 03 | 搬送可能な空パレット供給設備 → 補充対象マガジン | 在庫閾値到達・供給元準備・設備側許可 | 補充対象の残数確認、投入許可、補充実績 |
| 04 | 共通仮置き場 → 包装機投入側 | 作業者の手動要求と搬送許可 | 包装機への荷下ろし完了 |
| 05 | 共通仮置き場 → 倉庫指定位置 | 作業者の手動要求と搬送許可 | 指定位置への荷下ろし完了 |

- IDは開発上の定義であり、外部装置の信号番号と同一視しない。
- 02は01完了や包装完了だけでは生成しない。ラベル工程・出口状態を個別に検証する。
- 03は補充トリガー到達時に一度発行し、補充完了まで重複発行しない。供給元は搬送可能な候補から選ぶ。
- 04/05の詳細な例外・復旧手順はシナリオまたは追加要件で定義する。

## 5. 車両選定・充電

### 5.1 選定前提

状態、通信、安全・設備制約、電池残量、タスク適合性を検証し、実行可能な車両だけを候補にする。選定と実移動時間の計算は別処理にする。

### 5.2 比較モード

- `area_first`：要求の最初の荷受けエリアにいる候補を優先し、同条件では残量の低い候補を選ぶ。
- `low_battery_first`：エリアで候補を並べ替えず、残量の低い候補を選ぶ。
- 同率の最終決定は安定した車両ID順とする。
- 比較では両モードに同じ生産イベント列・設備状態・初期残量・閾値を与える。

### 5.3 バッテリー・充電

消費量、充電要求閾値、復帰閾値、充電速度、充電地点への移動時間、充電器台数はすべて外部シナリオ値とする。仮定の代表値を実測値として固定しない。充電地点への到着と充電開始は別イベント。充電設備が満杯の場合は待ち状態とする。

## 6. 配置・走行グラフ

- 実図とは独立した設備・荷役点・倉庫ロケーションのID台帳を持つ。
- ノード：荷役点、充電・待機点、シャッター停止点、交差点、旋回点、ロケーション。
- エッジ：接続、距離、通行方向、可否、速度、占有・シャッター条件を持つ。
- 設備位置と通行制約は承認済みシナリオから読込み、公開合成レイアウトと混同しない。
- 未確定の走行エッジと旋回点は「仮」と明示し、これだけから実距離・確定ETAを算出しない。
- シャッターごとの停止点と通行許可を扱い、許可信号を省略して通過完了させない。
- 製品入庫先はエリア単位だけでなく個別ロケーションまで保持する。
- 供給設備と補充対象は固定1対1にせず、準備状態と投入許可から組合せを選べる。

## 7. UIと再生

- 簡易2D平面図を中央に置き、設備アイコンと番号付き車両アイコンを重ねる。
- 上部：再生、一時停止、コマ送り、速度変更、タイムスライダー、シナリオ・選定方式。
- 車両パネル：現在位置、タスク、残量、状態（移動／荷役／待機／充電／充電待ち／異常）。
- 設備パネル：容量・占有、待ち列、包装・ラベル状態、空パレット準備、充電器占有。
- 履歴：時刻、イベント、対象ID、車両・設備、前後状態、ブロック理由。
- 比較：同一入力に対する入庫件数、タスク件数、待ち時間、滞留、空走時間、車両稼働率を並列表示。
- 仮設定・実績入力・確定設定の区別を表示し、CSVでイベント履歴と集計を出力する。

## 8. 検証と受入条件

1. 要求以前の割当、荷受け以前の荷下ろし、出口準備以前の02割当を拒否する。
2. バッファ・倉庫ロケーション・充電設備の容量超過を拒否する。
3. パレットID重複と車両への二重割当を拒否する。
4. 補充要求の重複、供給準備なしの補充、補充完了前の残数更新を拒否する。
5. 同じ入力の再実行で同じイベント履歴を生成する。
6. 時刻をシークしても表示状態はその時点の履歴スナップショットと一致する。
7. 比較モード間で変わるのは選定方式だけとし、外生入力を共通にする。
8. 未確定・仮定値による結果にはその区分を明示する。
9. 実シナリオの情報が公開用 fixture／ログ／画面キャプチャに紛れ込まないことを確認する。

## 9. データ構造（予定）

`Scenario`（入力と根拠区分）、`Layout`（ノード・エッジ）、`Equipment`（容量・状態）、`Pallet`（ID・工程）、`Task`（状態・優先度）、`AGF`（位置・状態・残量）、`Event`（時刻・順序・状態変化）、`Run`（シード・方式・検証結果）。

## 10. 現時点の実装範囲

実装済みハーネスは車両選定、合成イベント列の整合性検証、合成 fixture と自動テストに限定する。イベントキュー、経路計算、03の全物理工程、04/05、充電曲線、2D UI、衝突・インターロック、集計比較は**今後実装**する。
