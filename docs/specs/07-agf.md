# 07. AGF仕様書 v1.2

**独立仕様書**／関連：[全体](00-overview.md)・[設備](01-equipment.md)・[01](02-transport-01.md)・[02](03-transport-02.md)・[03](04-transport-03.md)・[04](05-transport-04.md)・[05](06-transport-05.md)

## 1. 目的

AGFごとのタスク適合性、割当、空走、荷役、積載搬送、位置、バッテリー残量、充電、待機を、搬送01～05で共通に使用する。画面はイベントエンジンから得た状態を描画し、アニメーション単独で完了時刻を決めない。

## 2. 基準シミュレーション設定

| 項目 | 値 | 区分 |
| --- | --- | --- |
| AGF | **4台** | 確認済み |
| 充電器 | **2台** | 確認済み |
| Battery初期値 | **各100%** | 初期シナリオ値 |
| 1搬送の消費 | **1～2%** | ユーザー確認範囲 |
| 代表消費値 | **1.5%** | 仮定・要確定 |
| 充電要求 | **40%以下** | シミュレーション設定 |
| 通常搬送復帰 | **80%** | シミュレーション設定 |
| 充電速度 | **1%=2.4分** | シミュレーション設定 |
| HP／充電スペース | 2台分、同じ場所を兼用 | 確認済み |
| 他の2台の初期／待機位置 | 未確定 | 後日入力 |

初期残量、消費、充電速度、閾値、充電器占有、初期位置は**シナリオから変更可能**にする。1.5%を実測確定値として固定しない。空走、荷役、タスク種別、走行距離への消費配分は未確定。

## 3. AGFデータ

`agfId`, `currentAreaId`, `locationId`, `position`, `direction`, `batteryPct`, `operationMode`, `state`, `currentTaskId`, `carriedPalletId`, `chargerId`, `updatedAt`。負荷・走行中・位置の確定／仮区分を区別する。

## 4. AGF状態

| 状態 | 意味 | 通常搬送選定 |
| --- | --- | --- |
| IDLE | 待機・タスク実行可能 | 対象 |
| MOVING_EMPTY | 荷受け点への空走 | 対象外 |
| PICKING | 荷受け処理 | 対象外 |
| MOVING_LOADED | パレット積載搬送 | 対象外 |
| DROPPING | 荷下ろし処理 | 対象外 |
| MOVING_TO_CHARGE | 充電場所への移動 | 対象外 |
| WAITING_CHARGE | 充電器空き待ち | 対象外 |
| CHARGING | 充電中 | 対象外 |
| ERROR / COMM_ERROR / MANUAL | 異常・通信異常・有人モード | 対象外 |

状態遷移には時刻、タスクID、理由を記録する。待機に戻るまでは新しい通常搬送を割り当てない。タスク中停止と正常待機は区別する。

## 5. AGF選定方式

候補は「待機中かつタスク実行可能」「バッテリー予約条件に適合」「設備・経路制約に反しない」車両に絞る。

- `area_first`（今回確定した通常選定方針）：**タスクの目的地エリア（荷下ろし先エリア）と現在エリアが一致する実行可能AGFを優先**し、その候補の中でバッテリー残量が少ない車両を優先する。同残量時のID順は既存ハーネスの暫定的な再現性ルールとし、正式な同率処理は未確定。**荷受け元エリア優先にはしない。**
- `low_battery_first`：エリア優先なしで低残量順、同率ならAGF ID順。
- どちらの方式でも、タスク実行中・充電中・充電待ち・異常・通信異常・有人モードは候補外。
- 目的地エリアに実行可能な候補が1台もいない場合の待機・他エリアからの選定／移動方針は未確定。勝手に低残量機を別エリアから確定割当しない。
- 開発ブランチの選定ハーネスは `task.destinationArea` を必須として目的地エリア優先を実装済み。目的地候補不在時は原則待機し、他エリアからの選定はシナリオで明示した仮定としてのみ許可する。
- 方式Bでも空走距離・走行時間の計算から現在位置を消さない。
- 比較時は生産入力列、設備、初期位置・残量、閾値などの外生条件を揃え、選定方式以外を変更しない。

**タスク種別の優先順位や割込み・予約方式は未確定**。01→02→03→04→05を固定の優先順位と断定しない。走行能力・充電余裕の予約判定は今後詳細設計する。

## 6. 搬送共通フロー

`REQUESTED → ASSIGNED → MOVING_EMPTY → WAIT_PICKUP_PERMISSION → PICKING → MOVING_LOADED → WAIT_DROPOFF_PERMISSION → DROPPING → COMPLETED → IDLE`。

1. 割当前に対象タスク・車両状態・設備可否を確認する。
2. AGF現在位置から最初の荷受け点へ移動する。
3. 荷受け位置到達・設備許可後に荷受けし、`carriedPalletId`を設定する。
4. 指定終点まで搬送し、受入許可後に荷下ろす。
5. 履歴・電池残量を更新し、タスクと積載を解除する。

区間時間は走行グラフと設定値から算出する。製品倉庫とパレタイズエリアの区間別方向・車線・干渉制御は[AGF通行・車線仕様書](09-traffic.md)の確認済み条件に従う。パレタイズエリアは通路1・2をそれぞれ双方向1車線、組合せで双方向2車線として扱い、AGF側の干渉制御でタスク中のAGF同士が通行可能になるよう制御する。各1車線区間内部の同時通過形態は未確定であり、無条件に二重占有を許さない。同じレーンに置きタスクが存在するときの搬送制限は占有範囲・開始／解除時点が未確定。隣接レーンへの2台同時進入は可能だが近接時に減速する（減速値・距離閾値は未確定）。**実走行線・旋回点・シャッター停止位置が未確定の間は仮描画にとどめ、確定ETAを出さない。** エリアへの進入・退出規則を優先する。

## 7. 充電共通フロー

1. バッテリー残量が40%以下になった時点で充電要求を作成する。
2. 実行中タスクがある場合の「中断か完了後か」は未確定。現在タスクを勝手に解放しない。
3. 充電場所へ移動して到着する。
4. 空きがある充電器1口を専有し、充電開始する。2口満杯の場合は充電待ち。
5. 1%=2.4分の設定で80%まで充電し、充電終了イベントを記録する。
6. 充電器を解放し、通常搬送の実行可否を再評価する。

充電器本体とAGF停車位置は別の地物として扱う。タスク実行不可・充電場所への未到着・満杯状態のまま充電開始しない。

## 8. 表示と計測

地図上はAGF1～4を色と番号で区別。機体の現在位置・タスク・積載パレット・残量・状態・待機理由・充電器占有をパネル表示する。履歴は空走時間、実搬送時間、荷役、充電移動、充電待ち、充電中を分けて集計する。使用した消費代表値等には「仮定」を表示する。

## 9. 受入条件・未確定

- AGF1台1タスク、積載パレット1件、充電器1口1台を強制する。
- 使用不可の車両を選定対象に含めない。
- 同じ候補からは選定方式に従い再現可能なIDを返す。
- 目的地（荷下ろし先）エリアの適格AGFを先に比較し、バッテリー残量が少ないものを優先する。荷受け元エリアで選定する既存コードを更新して整合を確認する。
- 充電場所未到着・充電器満杯時には充電中へ遷移しない。
- 40%以下の要求と80%での復帰をシナリオ値として検証可能にする。
- **未確定：** 初期位置、2枠以外での待機運用、タスク途中の充電切替、区間別消費・走行時間、充電位置への経路。
