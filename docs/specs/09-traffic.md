# 09. AGF通行・車線仕様書 v0.4（製品倉庫の補足・パレタイズエリア第1段階反映）

**独立仕様書**／関連：[全体マップ](08-map.md)・[設備](01-equipment.md)・[AGF](07-agf.md)・[経路指定ガイド](../route-annotation-guide.md)

> この文書は走行可否と車線の確認台帳。図面の矢印をそのまま「一方通行」「2車線」とは解釈しない。実図、実座標、現場識別情報、提供資料の名称はこの公開リポジトリに保存しない。

## 1. 確定の順序

1. **第1段階：通行できる場所を確定。** AGFが通過できる通路区間、設備への取付け通路、通行禁止区画、必要な通行許可を区間ごとに確定する。この段階では往来可能性、車線数、すれ違い可否、停止・旋回の安全性を確定しない。
2. **第2段階：第1段階で通行可能とされた区間ごとに、方向・車線数・すれ違いを確定。** 「双方向通行」と「2車線」を別属性とする。双方向1車線なら同時すれ違いの可否と退避／区間占有制御を別に確認する。
3. **第3段階（後続）：停止点・旋回点・優先順位・区間占有・距離・速度・時間を確認。** 前段階の未確定を推測で補完しない。

## 2. 判定単位と属性

**通路（Segment）**はシャッター、交差点、分岐、設備取付け口など、通行条件が変わる地点で分割する。設備・保管ロケーション自体と、そこへアクセスする走行通路を混同しない。

| 項目 | 値の例 | 確認段階 |
| --- | --- | --- |
| `segmentId` | 公開用の抽象ID | 初期 |
| `access` | `allowed` / `forbidden` / `unresolved` | 第1段階 |
| `accessScope` | 空走／積載／充電移動等、条件に差がある場合 | 第1段階 |
| `permission` | シャッター通行OKなど必要条件 | 第1段階 |
| `direction` | 双方向／指定方向のみ／未確定 | 第2段階 |
| `laneCount` | 1／2／その他／未確定 | 第2段階 |
| `simultaneousPassing` | 可／不可／制御条件付き／未確定 | 第2段階 |
| `turnStopStatus` | 確定／仮／未確定 | 第3段階 |
| `evidenceStatus` | 利用者確認／図示候補／未確定 | 全段階 |

通路方向、車線数、同時すれ違いは独立して記録する。矢印の本数は車線数を意味しない。製品パレットの保管マスは個別ロケーションであり、列間にAGFが進入する通路と区別する。利用者が「置き場ロケは通行可能」と補足したため、ロケーションへの進入・荷役は可能とするが、全マスを無条件に走行可能な道路としてグラフ化しない。

## 4. 第1段階の確定方法

対象となる区間の可否を利用者回答で確定する。第1段階で通行可能な区間を、通行方向・車線数・同時すれ違いの確認対象に移す。設備取付けや個別の列間通路で範囲が未確定の部分は、画像上で区間分割するまで未確定のまま保持する。

### 5.1 製品倉庫の「行」と「ブロック」の区別（Q11・Q12確定）

- **横一列（1行）単位：双方向・1車線。** AGFはその行を相互に通行できる。1車線であることから対向する2台の同時すれ違いを可能とは推測しない。
- **ブロック単位：双方向の往来が可能。** 複数の行で往来できるという管理単位の説明であり、ブロック全体が物理的に2車線という意味には置き換えない。
- 利用者が述べた「製品倉庫置き場まで2車線」は**横1行を単位に見た説明**。以前の「2車線アプローチ区間から1車線進入区間へ変化する実際の境界を特定する」という解釈を破棄する。道路の物理的な車線減少地点は新たに設定しない。
- WH-X-U、WH-X-L、WH-E-V、WH-W-Vなど、個別に2車線であると確認された幹線・接続通路の設定と、各アクセス区間の1車線設定はそのまま維持する。
- 図示された保管マスは個別の製品パレット置場。行内通路・ロケーション・停止点を別の管理対象とし、実際の行数・接続・格納方向は後続で確認する。

### 5.2 同一行の02要求・ロケーション予約（Q13・Q14確定）

1. 02の前提である対象PLの包装・ラベル貼付・出口搬出OKが成立した時点で、対象ロケーションと所属行を確認する。
2. **同じ行に既存の置きタスクがある場合、既存タスクの完了まで新しい02タスクを発行しない。** 発行待ち理由と対象PLを保持し、完了後に再判定する。
3. 同行の置きタスクがない場合、ロケーションの空き・予約状況・受入可否を確認する。利用可能なら02発行時に当該ロケーションを予約し、02タスクを発行する。
4. 発行待ちの要求はAGFに割り当てない。予約ロケーションは別のタスクに重複割当しない。荷下ろし完了時の在庫更新は搬送仕様に従う。

上記は**02発行制御**として確認済み。通過するだけのAGFまで同一行から排除する、02発行時に行全体の物理占有を開始する、05にも同一の発行ルールを適用する、といった拡張は未確定。置きタスクの占有開始・解除の厳密なイベント時点や取消時の予約解放は後続で決定する。

### 5.3 同一行・隣接行の干渉

- 同じ行に置きタスクがあれば、少なくともQ14により新規02の発行を保留する。
- **隣接する別の行に2台が同時進入することは可能**だが、近接時には減速する。減速率・距離閾値・開始／解除条件は未確定。
- 既に1車線・交互通行と確認した区間は対向車の同時すれ違いを不可とする。横1行内の同時すれ違いは未回答として残し、隣接行の同時進入と混同しない。

### 6.1 AGF同士の干渉制御

- **干渉制御はAGF側で実施する**ことを確認済みとする。
- **タスク実行中のAGF同士は、お互いが通行できるように制御する**。タスク中の対向車を恒久的な通行不可として扱わず、経路・交通制御で通過可能な状態を目指す。
- これは**同時すれ違い可能、2車線、無停止通過**を保証する意味ではない。譲り合い、停止、待機、優先順位、予約・排他、減速の具体ロジックは未確定。
- 1台が荷役中の設備前で他車が通れるか、エリア間通路および各シャッターでどう排他するかも未確定。

### 6.2 次回はパレタイズエリアの第2段階のみ確認

第1段階で確定したPZ-A1、PZ-A2、PZ-CON-W、PZ-CON-Eについて、進行方向・車線数・対向車の同時すれ違い可否を個別に質問する。必要に応じて設備への取付け点とOT1～OT3の個別通路も区間分割して確認する。今回の回答から車線数を作らない。

## 7. 受入条件・更新規則

- 第1段階で`forbidden`の区間は経路探索対象にしない。
- `unresolved`は通行可能扱いにせず、確認待ちを表示する。
- 片方向を確定するまでは、図示の矢印だけで逆方向の可否を推測しない。
- 製品倉庫で双方向2車線・同時すれ違い可能と確認済みの区間はその条件を使用する。1車線・交互通行と確認済みの区間は対向車の同時すれ違いを許さない。横1行内の同時すれ違いは未確定とする。
- パレタイズエリアは通行可能範囲と接続先だけが第1段階で確定。方向・車線数・同時すれ違いは個別回答まで未確定とする。
- 02は同じ行の既存置きタスクが完了する前に発行しない。発行時に空き・予約を確認し、利用可能なロケーションを予約する。
- 実ルート、停止点、旋回位置、衝突回避が未確定の段階では実機相当の安全性や確定ETAを主張しない。
- 変更ごとに改訂番号と対象区間を記録し、ユーザー確認済み事項を繰り返し未確定扱いに戻さない。
