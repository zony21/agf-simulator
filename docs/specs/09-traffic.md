# 09. AGF通行・車線仕様書 v0.2（第1段階反映）

**独立仕様書**／関連：[全体マップ](08-map.md)・[設備](01-equipment.md)・[AGF](07-agf.md)・[経路指定ガイド](../route-annotation-guide.md)

> この文書は走行可否と車線の確認台帳。図面の矢印をそのまま「一方通行」「2車線」とは解釈しない。実図、実座標、現場識別情報、提供資料の名称はこの公開リポジトリに保存しない。

## 1. 確定の順序

1. **第1段階：通行できる場所を確定。** AGFが通過できる通路区間、設備への取付け通路、通行禁止区画、必要な通行許可を区間ごとに確定する。この段階では往来可能性、車線数、すれ違い可否、停止・旋回の安全性を確定しない。
2. **第2段階：第1段階で通行可能とされた区間ごとに、方向・車線数・すれ違いを確定。** 「双方向通行」と「2車線」を別属性とする。双方向1車線なら同時すれ違いの可否と退避／区間占有制御を別に確認する。
3. **第3段階（後続）：停止点・旋回点・優先順位・区間占有・距離・速度・時間を確認。** 前段階の未確定を推測で補完しない。

## 2. 判定単位と属性

**通路（Segment）**はシャッター、交差点、分岐、設備取付け口など、通行条件が変わる地点で分割する。設備・保管ロケーション自体と、そこへアクセスする走行通路を混同しない。

| 項目 | 値の例 | 確認段階 |
| --- | --- | --- |
| `segmentId` | 公開用の抽象ID | 初期 |
| `access` | `allowed` / `forbidden` / `unresolved` | 第1段階 |
| `accessScope` | 空走／積載／充電移動等、条件に差がある場合 | 第1段階 |
| `permission` | シャッター通行OKなど必要条件 | 第1段階 |
| `direction` | 双方向／指定方向のみ／未確定 | 第2段階 |
| `laneCount` | 1／2／その他／未確定 | 第2段階 |
| `simultaneousPassing` | 可／不可／制御条件付き／未確定 | 第2段階 |
| `turnStopStatus` | 確定／仮／未確定 | 第3段階 |
| `evidenceStatus` | 利用者確認／図示候補／未確定 | 全段階 |

通路方向、車線数、同時すれ違いは独立して記録する。矢印の本数は車線数を意味しない。ピンク等で表示した保管マスは**製品パレットロケーション**であり、マス全体が走行可能な道路とは扱わない。

## 3. 第1段階：通行できる場所

### 3.1 既に確認されている運用制約

| 論理区分 | AGF通行 | 補足 |
| --- | --- | --- |
| 製品倉庫の通常出入口 | 東側出入口を使用 | 出入ルール確認済み。車線数は未確定 |
| 製品倉庫の西側出入口 | **使用しない** | AGFの経路候補から除外 |
| パレタイザエリアの入口 | 西側から進入 | 運用ルール確認済み |
| パレタイザエリアの出口 | 東側から退出 | 運用ルール確認済み |
| 空パレット保管マス | AGFの03直接荷受け対象外 | 整列機と保管場所を区別 |
| 個別製品保管マス | 個別ロケーションを搬送先として扱う | マス内部を走行路として自動登録しない |

上表は全走行線の確定を意味しない。シャッターの開閉・通行可能信号の前提も、単なる走行線と区別する。

### 3.2 製品倉庫の通行可否台帳（第1段階の回答反映）

以下の通行可否は利用者の回答で確定。**通行可能とは「その区間をAGFの走行候補として扱える」ことだけであり、双方向・車線数・同時すれ違い・旋回可否を含まない。** 各IDは区間群を識別するための抽象IDであり、厳密な分割・座標を確定しない。

| 区間ID | 通行区間 | 第1段階：通行可否 | 第2段階：方向／車線／すれ違い |
| --- | --- | --- | --- |
| WH-X-L | 下段の防火シャッター経由の東西接続通路 | **通行可能（確認済み）** | 未確定 |
| WH-E-V | 東側縦方向通路 | **全区間通行可能（確認済み）** | 未確定 |
| WH-W-V | 西側縦方向通路 | **全区間通行可能（確認済み）** | 未確定 |
| WH-W-A | 西側・上段保管区画への横方向アクセス | **通行可能（確認済み）** | 未確定 |
| WH-W-B | 西側・中央保管区画への横方向アクセス | **通行可能（確認済み）** | 未確定 |
| WH-W-C | 西側・下段保管区画への横方向アクセス | **通行可能（確認済み）** | 未確定 |
| WH-E-A | 東側・上段保管区画へのアクセス | **通行可能（確認済み）** | 未確定 |

| WH-X-U | 上段の防火シャッター経由の東西接続通路 | **代表入庫経路として通過可能な区間を図示・確認済み** | 全区間の詳細・方向等は未確定 |
| WH-ROW | 製品パレットのロケーション列間に進入する通路 | **通路が存在し、AGFが進入可能（確認済み）** | 個別通路の本数・接続範囲・方向等は未確定 |

西側上・中央・下／東側上・下は、この確認で使った区間群のラベルであり、実際の道路数やすべての分岐点を表すものではない。**ロケーションを示す四角は製品パレットの置場**。マスを走行路とみなさず、列間の通路と保管マスを別に登録する。

### 3.3 個別の倉庫保管順序

**「奥から順にパレットを設置する想定」**を保管方針の検討条件として記録する。走行可否や車線数を示す情報ではない。奥の基準方向、列ごとの格納順序、格納可否・予約、各ロケーションの停止位置は今後別途確定する。既存の個別ロケーション管理は維持する。

### 3.4 既に確定した利用制約／今も未確定の事項

- 倉庫東側出入口を使用し、西側出入口はAGFが使用しない。
- シャッターの通行許可確認は経路の通行可否と別に必要。
- 今回の回答は**製品倉庫内の通行可否**を更新したもので、パレタイザ側の個別通路、各シャッター停止座標、旋回可能位置を確定しない。
- 走行方向・各区間の車線数・同時すれ違いは今回の回答からは判定しない。

## 4. 第1段階の確定方法

対象となる区間の可否を利用者回答で確定する。第1段階で通行可能な区間を、通行方向・車線数・同時すれ違いの確認対象に移す。設備取付けや個別の列間通路で範囲が未確定の部分は、画像上で区間分割するまで未確定のまま保持する。

## 5. 第2段階：方向・車線・往来条件（回答待ち）

第1段階で通行可能と確定した区間／区間群について、**方向**、**車線数**、**同時すれ違い可否**を別々に確認する。通路内で別ルート・別車線になっている場合は「区間内で異なる」と回答し、後から区間分割する。

| 対象 | 方向 | 車線数 | 同時すれ違い | 状態 |
| --- | --- | --- | --- | --- |
| WH-X-L（下段東西接続） | 未確定 | 未確定 | 未確定 | 第2段階回答待ち |
| WH-E-V（東側縦通路） | 未確定 | 未確定 | 未確定 | 第2段階回答待ち |
| WH-W-V（西側縦通路） | 未確定 | 未確定 | 未確定 | 第2段階回答待ち |
| WH-W-A/B/C（西側横方向アクセス） | 未確定 | 未確定 | 未確定 | 各区間で回答待ち |
| WH-E-A/B（東側保管アクセス） | 未確定 | 未確定 | 未確定 | 各区間で回答待ち |
| WH-X-U（上段東西接続の代表経路区間） | 未確定 | 未確定 | 未確定 | 回答待ち。全区間への外挿禁止 |
| WH-ROW（列間通路） | 未確定 | 未確定 | 未確定 | 通路を図面で分割後に個別適用 |

- **双方向**と**2車線**は同義ではない。1車線を双方向で交互通行する場合、同時すれ違い可否と制御方法を別に記録する。
- 図面に描かれた青／オレンジの線、並列矢印の本数から車線数や一方通行を推測しない。
- 第1段階で未確定のWH-SERVICEを通行可能経路として扱ったり、第2段階の確定対象に含めたりしない。

## 6. 受入条件・更新規則

- 第1段階で`forbidden`の区間は経路探索対象にしない。
- `unresolved`は通行可能扱いにせず、確認待ちを表示する。
- 片方向を確定するまでは、図示の矢印だけで逆方向の可否を推測しない。
- 双方向でも車線数・同時すれ違いを確定するまでは、AGF2台の同時通過可能としない。
- 実ルート、停止点、旋回位置、衝突回避が未確定の段階では実機相当の安全性や確定ETAを主張しない。
- 変更ごとに改訂番号と対象区間を記録し、ユーザー確認済み事項を繰り返し未確定扱いに戻さない。
